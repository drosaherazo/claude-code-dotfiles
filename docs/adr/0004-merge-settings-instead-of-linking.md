# Merge settings.json instead of linking it

Unlike the other files, `settings.json` is merged, not linked. Claude Code rewrites it on its own (accepted permissions, `/config` changes) and it holds per-machine values such as the absolute path to the status line script, so a linked copy would keep the repo dirty and break on another operating system. The base, the profile and the local layer each keep a `settings.json` (ADR 0001, ADR 0002); the installer merges them into each machine's file with the local layer winning over the profile, the profile over the base, and the base over the machine's existing keys, while every other key is kept. Objects merge key by key and lists are combined without repeats, so a machine keeps what it accepted (such as permissions); any other value is replaced. An entry removed from a layer's list therefore stays on machines that already have it, and the drift check points it out. Changes made in `/config` that should travel are moved into the repo by hand, and the drift check points them out.
